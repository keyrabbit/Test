Risks

#1 The character is the product critical · open

A focus timer is a commodity; the reason someone keeps this on screen is that they like the creature. The shipping mascot is still a placeholder and the reference sheet is on a human's clock. Every downstream asset (poses, decorations, app icon, Steam capsules) is conditioned on it, so a late or weak sheet compounds.

Mitigation. Prompt A issued to the owner on day one as issue #2. The placeholder is wired to the full animation rig through art/manifest.json so the swap touches art, not behaviour.

https://github.com/keyrabbit/Pet/issues/2

#2 Dashboard cannot auto-publish low · mitigated

DASHBOARD_PUSH_TOKEN does not exist, so CI cannot push to keyrabbit/Test.

Mitigation. Dashboard published to docs/dashboard/ in this repo and mirrored by hand to Test/pet/. See DECISIONS.md D8.

#3 MSIX build on a hosted runner is unverified medium · open

Packaging for the Store needs Windows SDK tooling (MakeAppx) that has not yet been exercised on a GitHub-hosted runner. Discovering a gap here late would block submission.

Mitigation. CI builds both packaging targets from the same commit starting at G0, so a gap surfaces immediately rather than at G5.

#4 Only 200% scaling is testable on the dev host medium · open

The development display is fixed at 2880x1920 @ 200%. 100% and 150% cannot be exercised locally without changing display settings.

Mitigation. Windows Sandbox is used as a second DPI/theme surface, and display set-dpi is available there. Full matrix runs at G5.
